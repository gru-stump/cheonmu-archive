# 천무 관리자 쉬운 사용성 개편 설계

## 목적

천무 관리자 화면을 개발 도구가 아니라 한 명의 비개발자 소유자가 이야기 생성과 검토를 안전하게 운영하는 도구로 바꾼다. 기술 용어와 내부 상태 코드는 기본 화면에서 숨기고, 현재 상황·발생 시각·다음 행동을 쉬운 한국어로 보여준다.

이번 개편은 관리자 화면 전체, 설정 저장 경계, 모델 정보 조회, 비밀키 삭제, 접속 생성 실행 흐름을 포함한다. 실제 유료 이야기 생성은 구현·검증 과정에서 실행하지 않으며 별도 사용자 승인 뒤에만 수행한다.

## 사용 원칙

1. 기본 화면에는 사용자가 결정해야 하는 값만 보여준다.
2. 시스템용 값은 자동 계산하고 `고급 설정`에 접어 둔다.
3. 상태는 기술 코드가 아니라 의미와 다음 행동으로 설명한다.
4. 모든 날짜와 시간은 `Asia/Seoul` 기준의 정확한 연월일·시분과 읽기 쉬운 상대 표현을 함께 보여준다.
5. 비용이 발생하는 행동은 실행 전 예상 최대 비용을 원화로 확인받는다.
6. 비밀키와 서버 비밀값은 브라우저 응답·로그·번들에 노출하지 않는다.
7. 색상만으로 상태를 전달하지 않고 아이콘·제목·설명을 함께 사용한다.

## 정보 구조와 화면

### 오늘

- 상단에 `지금 할 일`, `이야기 생성 현황`, `이번 달 예산`을 배치한다.
- 내부 이름 `Generation queue`는 `이야기 생성 현황`으로 바꾼다.
- 작업은 `접속 이야기`, `정기 이야기`, `직접 요청한 이야기`처럼 출처를 설명한다.
- 기본 상태 문구는 다음과 같다.
  - `queued / attempt 0` → `생성 대기 중`
  - `running` → `AI가 이야기를 만드는 중`
  - `retry-wait` → `잠시 후 다시 시도할 예정`
  - `completed` → `생성 완료`
  - `failed / dead-letter` → `여러 번 시도했지만 생성하지 못함`
  - `provider_outcome_unknown` → `AI 요청 결과를 확인하지 못해 안전하게 중단함`
- 각 작업에 요청 시각, 마지막 변경 시각, 완료 또는 중단 시각, 다음 재시도 시각을 표시한다.
- 기술 코드와 시도 토큰 등은 소유자에게도 기본 노출하지 않고 `기술 정보 보기`에 안전한 코드만 표시한다.

### 초안

- 생성된 버전이 없는 내부 대기 초안은 목록에 표시하지 않는다.
- 목록은 `검토 필요`, `승인됨`, `보관됨`처럼 행동 중심으로 묶는다.
- 상세 화면은 본문을 가장 크게 보여주고, 연속성 판정은 `문제 없음`, `확인 필요`, `승인 불가`로 설명한다.
- 실패한 생성 작업은 초안이 아니라 오늘 화면의 작업 기록에서 확인한다.

### 기억

- 화면 이름과 설명을 `AI가 지켜야 할 설정`으로 풀어 쓴다.
- `canon`, `continuity`, `feedback`, `unresolved`를 각각 `확정 설정`, `이어지는 사실`, `수정 지침`, `아직 정하지 않은 설정`으로 표시한다.
- 원본 내부 유형은 데이터와 기술 정보에서만 유지한다.

### 일정

- `언제 어떤 이야기를 만들지`를 중심으로 설명한다.
- 수동 생성 허용과 자동 일정 허용을 분명히 구분한다.
- 정기 cron이 비활성일 때는 `자동 일정 정책은 켜져 있지만 실행 일정은 없음`처럼 실제 상태를 설명한다.
- 다음 실행 시각은 서울 시간으로 표시한다.

### 설정

기본 화면은 `간편 설정`이며 다음 항목만 노출한다.

1. AI 제공자
2. API 키 상태와 등록·교체·삭제
3. 사용 가능한 모델 선택
4. 월 예산과 하루 예산(원화)
5. 수동 생성 허용
6. 자동 일정 허용
7. 저장

`고급 설정`에는 입력·출력 토큰 한도, 모델 단가, 단가 확인일, 유효 기간, 경고·위험 기준, 환율을 둔다. 각 항목에는 한 문장 설명과 권장값 복원 기능을 제공한다.

## 모델 목록과 가격

- 브라우저는 제공자 API를 직접 호출하지 않는다.
- 같은 출처의 관리자 API가 소유자 인증을 확인한 뒤 Supabase Edge 함수에 요청한다.
- Edge 함수는 Vault에 저장된 해당 제공자 키로 모델 목록을 조회하고, 이야기 생성 계약과 호환되는 모델만 반환한다.
- 응답은 모델 ID, 표시 이름, 짧은 용도 설명, 품질·속도·비용 등급, 추천 여부, 가격 확인일만 포함한다.
- API 키가 없거나 제공자 조회가 실패하면 서버에 포함된 검증된 호환 모델 목록을 보여주되 `현재 계정에서 사용 가능한지는 키 등록 후 확인`이라고 표시한다.
- 모델 API가 가격을 제공하지 않으므로 가격은 공식 제공자 문서로 검증한 서버 측 카탈로그에서 가져온다. 카탈로그에는 출처와 확인일을 기록한다.
- 사용자가 모델을 선택하면 입력·출력 단가와 권장 토큰 한도를 자동 적용한다. 사용자가 고급 값을 직접 바꾼 경우에는 자동 적용 여부를 명확히 표시한다.

## 원화 예산 입력

- 월 예산에는 `5천원`, `1만원`, `3만원` 빠른 선택과 직접 입력을 제공한다.
- 하루 한도는 월 예산을 기준으로 추천하되 사용자가 바꿀 수 있다.
- 예상 생성 가능 횟수는 선택 모델의 최대 예상 비용으로 보수적으로 계산하고 `대략적인 횟수`라고 표시한다.
- 저장 직전에 원화 값을 현재 설정 환율로 USD 마이크로 단위로 변환한다.
- 화면에는 사용 금액, 예약 금액, 남은 금액을 원화 우선으로 표시하고 달러는 고급 정보로 둔다.
- 숫자 입력은 천 단위 구분, `원` 접미사, 음수·비정상 값 즉시 안내를 지원한다.

## 비밀키 관리

- 키 값은 저장 후 다시 표시하지 않고 `연결됨` 여부와 마지막 변경 시각만 보여준다.
- `API 키 삭제`는 별도 확인 대화상자를 사용한다.
- 삭제는 서버의 단일 원자적 작업으로 처리한다.
  1. 소유자와 대상 제공자를 확인한다.
  2. Vault 비밀을 삭제한다.
  3. 해당 제공자를 비활성화한다.
  4. 수동 생성과 자동 일정 정책을 모두 정지한다.
  5. 감사 기록을 남긴다.
- 삭제해도 기존 초안·기억·비용 장부·작업 기록은 보존한다.
- 삭제 성공 응답에는 비밀 값이나 Vault 식별자를 포함하지 않는다.

## 접속 이야기 즉시 생성

- `접속 이야기 만들기`를 누르면 현재 모델과 설정으로 계산한 예상 최대 비용을 원화로 보여준다.
- 사용자가 확인해야만 작업을 생성한다.
- 접속 작업을 큐에 저장한 뒤 신뢰된 Edge 경계가 생성 worker를 즉시 깨운다. 브라우저에는 dispatch token이나 service-role 키를 전달하지 않는다.
- 화면은 작업 ID를 폴링하여 `대기 → 생성 중 → 완료/실패`로 갱신한다.
- worker 호출에 실패해도 같은 작업만 남기고 새 작업을 중복 생성하지 않는다.
- 기존 정기 cron 활성 여부와 무관하게 사용자 확인을 받은 접속 작업만 즉시 실행한다.
- 대기 작업은 제공자 호출 전에만 취소할 수 있다. 실패·완료 기록은 삭제하지 않고 최근 기록에서 접어 둘 수 있다.

## 시간과 기록 표시

- API는 작업의 `createdAt`, `scheduledFor`, `retryAt`, `completedAt`, `failedAt`을 안전한 ISO 시각으로 제공한다.
- 화면은 `오늘 오후 10:14`와 `2026.08.16 22:14`를 함께 표시한다.
- 날짜가 다른 경우 상대 표현 대신 전체 날짜를 우선한다.
- 서버 시간과 브라우저 시간 차이에 영향받지 않도록 DB 시각을 기준으로 한다.

## 서버와 데이터 변경

- 관리자 same-origin API에 모델 목록 조회와 비밀키 삭제 경계를 추가한다.
- `manage-settings` Edge 함수에 소유자 인증된 모델 조회와 키 삭제 작업을 추가한다.
- 필요한 경우 additive migration으로 키 삭제 원자 작업, 작업 취소, dashboard 시간 projection을 추가한다. 과거 migration은 수정하지 않는다.
- `run-schedules`의 접속 작업 생성 뒤 `run-generation-worker`를 신뢰된 서버 간 요청으로 깨우는 경계를 추가한다.
- 응답은 allowlist projection만 사용하며 provider 원문 오류와 비밀값을 전달하지 않는다.

## 오류 경험

- 오류는 `무슨 일이 있었는지`, `비용이 발생할 수 있는지`, `사용자가 할 일`의 세 줄로 설명한다.
- 예시:
  - `모델 목록을 불러오지 못했습니다. 저장된 기본 목록을 보여드립니다. API 키 상태를 확인해 주세요.`
  - `AI 요청 결과를 확인하지 못했습니다. 중복 결제를 막기 위해 자동 재실행하지 않았습니다.`
  - `예산이 부족해 생성을 시작하지 않았습니다. 비용은 발생하지 않았습니다.`
- 내부 오류 코드는 `기술 정보 보기`에 복사 가능한 값으로만 제공한다.

## 시각·접근성 기준

- 기존 아이보리·먹색 기반 디자인 언어는 유지하되, 한 화면의 주요 행동은 하나만 강하게 강조한다.
- 카드 제목 아래에 쉬운 설명을 배치하고 상태·비용·시각을 일정한 순서로 정렬한다.
- 데스크톱은 요약과 세부를 2열로, 모바일은 단일 열과 고정 하단 주요 행동을 사용한다.
- 버튼과 입력은 최소 44px 터치 영역, 명확한 포커스, 레이블 연결을 유지한다.
- 상태 색상은 텍스트와 아이콘을 반드시 동반한다.

## 검증

- TDD로 API, Edge, DB RPC, 상태 변환, 원화 계산, 모델 필터, 키 삭제, 접근성 회귀를 먼저 작성한다.
- 관리자 단위 테스트와 빌드, Edge 단위·타입 검사, pgTAP, 실제 2연결 동시성, additive upgrade를 검증한다.
- 로컬 fake provider로 접속 즉시 생성 전체 흐름과 중복 방지를 검증한다.
- 실제 Vercel 배포에서 소유자 인증, 모델 목록의 비밀 비노출, 키 삭제 실패 닫힘, 쉬운 상태·시간 표시를 확인한다.
- 실제 유료 제공자 생성은 구현 검증에 포함하지 않고 사용자에게 별도 승인을 요청한다.

## 완료 조건

- 비개발자가 기본 설정 화면에서 기술 단가와 토큰 값을 직접 입력하지 않고 저장할 수 있다.
- 제공자와 모델을 선택 목록으로 고를 수 있고 추천 이유를 이해할 수 있다.
- API 키를 안전하게 삭제할 수 있다.
- 모든 관리자 화면의 핵심 상태와 오류가 쉬운 한국어로 표시된다.
- 작업마다 서울 기준 발생 시각과 다음 행동이 보인다.
- 접속 이야기는 비용 확인 뒤 즉시 시작되며 중복 작업이나 비밀 노출이 없다.
- 기존 보안·예산·정사 연속성 경계가 유지된다.
